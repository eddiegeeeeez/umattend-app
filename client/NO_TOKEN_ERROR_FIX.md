# Fix: "No Token Provided" Error After Onboarding

## Problem
After successful onboarding, when the user tries to continue to the dashboard, an error occurs: "Onboarding failed - No token provided"

## Root Cause Analysis

### What Happens During Onboarding:

1. **Initial State**: User has old JWT from Google auth (with `done_onboarding: false`)
2. **Onboarding Submission**: Backend processes onboarding and returns new JWT
3. **New JWT**: Contains updated user data (with `done_onboarding: true`)
4. **Frontend Updates**: Calls `setAuth()` with new access token
5. **❌ Problem**: Immediately after updating auth, the `/user` API query tries to fetch data
6. **❌ Race Condition**: The API call happens before the axios interceptor picks up the new token
7. **❌ Result**: API call made without Authorization header → "No token provided" error

### Two Issues:

#### Issue 1: Autogenerated API Client Not Using Custom Axios Instance
The autogenerated API client (`client.gen.ts`) was creating its own axios instance instead of using our custom axios instance with interceptors that automatically add the Authorization header.

**Original code:**
```typescript
export const client = createClient(createConfig<ClientOptions2>({
    baseURL: '/api/v1'
    // ❌ No axios instance specified, creates default one without interceptors
}));
```

#### Issue 2: User Query Triggering Immediately After Token Update
The `useQuery` for fetching user data was enabled for all authenticated users, including right after the token update from onboarding.

**Original code:**
```typescript
const { data: userData } = useQuery({
  ...getUserOptions(),
  enabled: isAuthenticated(), // ❌ Triggers immediately after setAuth()
  staleTime: 5 * 60 * 1000
});
```

## Solution

### Fix 1: Configure API Client to Use Custom Axios Instance

Updated `src/api/client/client.gen.ts` to use our custom axios instance with interceptors:

```typescript
// This file is auto-generated by @hey-api/openapi-ts

import { type ClientOptions, type Config, createClient, createConfig } from './client';
import type { ClientOptions as ClientOptions2 } from './types.gen';
import axiosInstance from '@/lib/axios';  // ✅ Import custom axios

export const client = createClient(createConfig<ClientOptions2>({
    baseURL: '/api/v1',
    axios: axiosInstance  // ✅ Use our custom axios instance with interceptors
}));
```

**Benefits:**
- All API calls now use the same axios instance
- Authorization header automatically added by interceptor
- Token refresh logic applies to all requests
- Consistent error handling across all API calls

### Fix 2: Disable User Query After Onboarding

Updated the query to not trigger after onboarding is complete:

```typescript
const { data: userData } = useQuery({
  ...getUserOptions(),
  enabled: isAuthenticated() && !isDoneOnboarding(), // ✅ Disable after onboarding
  staleTime: 5 * 60 * 1000
});
```

**Why this works:**
- Query only runs for authenticated users who haven't completed onboarding
- After `setAuth()` updates the token with `done_onboarding: true`, query stops
- No race condition - no API call triggers immediately after token update

### Fix 3: Improved Onboarding Success Handler

```typescript
const onboardingMutation = useMutation({
  ...postUserOnboardingMutation(),
  onSuccess: (data) => {
    if (data.success && data.data?.access_token) {
      const currentRefreshToken = refreshToken;
      
      // Update auth store with new access token
      if (currentRefreshToken) {
        setAuth(data.data.access_token, currentRefreshToken);
      }

      toast.success('Profile completed successfully!', {
        description: 'Welcome to the event management system.'
      });

      // Redirect after a longer delay to ensure state is updated
      setTimeout(() => {
        router.push('/events');
      }, 800); // ✅ Increased from 500ms to 800ms
    } else {
      toast.error('Onboarding failed', {
        description: 'Invalid response from server. Please try again.'
      });
    }
  },
  // ... error handler
});
```

**Improvements:**
- Better null checks for response data
- Increased redirect delay to ensure state updates propagate
- Added error handling for invalid responses

## How the Axios Interceptor Works

Our custom axios instance (`src/lib/axios.ts`) has request interceptors:

```typescript
axiosInstance.interceptors.request.use(
  (config) => {
    const { accessToken } = useAuthStore.getState(); // ✅ Reads from store on each request

    if (accessToken) {
      config.headers.Authorization = `Bearer ${accessToken}`; // ✅ Adds header
    }

    return config;
  },
  (error) => {
    return Promise.reject(error);
  }
);
```

**Key Point**: The interceptor calls `useAuthStore.getState()` on **every request**, so it always gets the latest token from the store.

