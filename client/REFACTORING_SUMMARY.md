## API Request Structure

The onboarding mutation sends:
```typescript
{
  body: {
    department: string,
    program: string
  }
}
```

And expects a response with:
```typescript
{
  success: boolean,
  message: string,
  data: {
    access_token: string,
    user: {
      id: string,
      email: string,
      name: string,
      department: string,
      program: string,
      done_onboarding: boolean
    }
  }
}
```

## User Flow

1. User lands on onboarding page (protected route)
2. User sees their information from auth token (name, ID, email)
3. User selects department from dropdown
4. Program dropdown becomes enabled and populated based on department
5. Submit button becomes enabled when both fields are selected
6. On submit:
   - Form validates via react-hook-form
   - Mutation fires with proper loading state
   - Success: Toast notification + token update + redirect to /events
   - Error: Toast notification with error message from API
